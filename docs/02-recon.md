# Этап 2 — Ручная разведка точек инъекции

## Что делаем
До запуска автоматизированных инструментов — вручную находим потенциальную точку SQL-инъекции
и понимаем, как приложение обрабатывает ввод. Это показывает понимание темы, а не просто "нажал кнопку в sqlmap".

## Шаги

1. Открыть раздел **SQL Injection** в DVWA.
2. В поле User ID ввести одинарную кавычку: `'`
3. Отправить форму — ожидаем SQL-ошибку в ответе (это подтверждает, что ввод не экранируется).
4. Открыть DevTools браузера (или Burp Suite, если установлен в Codespaces) → вкладка Network.
5. Посмотреть исходный HTTP-запрос:
   - метод (GET)
   - параметр (`id`)
   - куки сессии (`PHPSESSID`, `security`)
6. Зафиксировать вывод: какая именно ошибка возникла, какую СУБД она выдаёт (обычно видно "MySQL" в тексте ошибки).

## Ожидаемый результат
- Подтверждено, что параметр `id` не экранируется и напрямую попадает в SQL-запрос
- Определена СУБД (MySQL) по тексту ошибки
- Зафиксирована структура HTTP-запроса для дальнейшей передачи в sqlmap
